#标题
IRQ 352 亲和性修改失败

#内核版本
openEuler 22.03 LTS SP3

#问题现象
执行 echo 2 > /proc/irq/352/smp_affinity_list 返回 Input/output error。cat /proc/irq/352/effective_affinity_list 显示 0-95，dmesg 中出现 managed IRQ affinity is immutable。业务侧希望把该中断固定到 NUMA node1，但手动写入一直不生效。

#问题根因
IRQ 352 是网卡驱动申请的 managed MSI-X vector，内核会根据队列和 CPU online 状态自动管理亲和性。该类中断不允许用户直接写 smp_affinity_list，因此不是权限问题，也不是 irqbalance 抢占导致。

#解决方案
不要直接修改 /proc/irq/352/smp_affinity_list。应通过 ethtool -X 调整网卡 RSS 队列映射，或在驱动加载参数中配置队列数量；需要跨 NUMA 调整时，先确认对应队列的 local_cpulist，再让业务线程绑定到同 NUMA 节点。
